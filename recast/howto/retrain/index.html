    Retrain¶

    The pipeline takes structure pairs (a calculated structure and the experimental structure it corresponds to, with the same atoms in the same order) to a release folder that recast correct uses. The commands below run it on a synthetic set built from ASE prototypes, so that every step can be tried without data; tests/test_pipeline.py runs the same commands with four epochs per member in about one minute on one core.

    1. Pairs¶

    recast toy -o work/pairs.json

    writes 39 pairs: fcc, bcc and hcp cells of seven metals and B2, L1_2 and L1_0 alloys as calculated structures, each deformed by a known strain and known displacements as its experimental structure (recast.toy). Your own pairs file has the same layout, a JSON list of

    {"key": "...", "functional": "PBE", "Z": [...],
 "calculated": {"L": [[...], [...], [...]], "f": [[...], ...]},
 "experimental": {"L": [[...], [...], [...]], "f": [[...], ...]}}

    with cell rows L in angstrom and fractional coordinates f.

    2. Targets¶

    recast targets work/pairs.json -o work/targets.h5

    computes the strain and displacement targets of every pair (recast.targets): the Green-Lagrange strain from the calculated to the experimental cell, in the lattice basis that fits the atoms best, and the displacements where the atoms of the two structures correspond.

    3. Features¶

    recast features work/targets.h5 -o work/data --inputs toy

    computes the inputs of the calculated structures and stores them with the targets. --inputs toy uses ASE's EMT potential and radial descriptors; --inputs shipped uses MACE-OMAT-0 (descriptors, the exact Green-Lagrange Hessian and the D3 relaxations), and --inputs MODULE:FUNCTION your own featurizers (Use another MLIP).

    For many structures, split the work into shards (on a GPU with --device cuda) and merge them:

    recast features work/targets.h5 -o work/shards/0 --inputs shipped --device cuda --shard 0/8
...                                                                              # shards 1 to 7, e.g. as array tasks
recast features work/targets.h5 -o work/data --merge work/shards/*

    Each structure is stored as soon as it is done; --resume continues an interrupted shard in its folder. The merged folder is the same as the folder of one run over all structures.

    4. Partitions¶

    recast split work/data -o work/parts.json --keys 42,43 --test 0.15 --val 0.15

    draws one random partition into training, validation and test structures per key: a permutation by the key, the test set first, then the validation set from the rest (--val is the share of the rest). The paper used ten keys (42 to 51), 1,806 test pairs per key (10 %) and 10 % of the rest for validation; data/structure_pairs.csv lists its assignment of the pairs. When one material has several pairs (for example several experimental reports), give a CSV key,unit with --units, so that all pairs of a material fall on one side.

    Every choice of settings is made on the development pool, the pairs in no test set, so that each test set is scored once by the final networks. The development folds and the grouped evaluation folds of the paper:

    recast groups work/data -o work/groups.csv                       # reduced formula, prototype, chemical system
recast folds --partitions work/parts.json --groups work/groups.csv -o work/folds.json \
    --random 3000,3010 --formula 3100 --prototype 3200 --seed 20261022
recast folds --partitions work/parts.json -o work/folds_more.json --add-to work/folds.json --random 3040 --seed 7
recast grouped work/data --groups work/groups.csv -o work/grouped.json --prototype 4200 --chemsys 4300
recast fraction work/parts.json -o work/parts_f25.json --fraction 0.25            # learning curves
recast table --splits work/parts.json --folds work/folds.json work/grouped.json -o work/pairs.csv

    recast table --columns ids.csv adds further identifier columns after the first (a CSV keyed by the pair), as the COD ids and the functional of data/structure_pairs.csv.

    Five folds per family; the random families are drawn with one generator, the formula and prototype families keep each group on one side; a later round of choices gets a fresh random family (--add-to) that no earlier choice was scored on. The grouped evaluation folds hold out every prototype (4200 to 4204) or every chemical system (4300 to 4304) once. These commands rebuild the paper's development folds, grouped folds and training fractions exactly from its pairs and splits, and data/structure_pairs.csv byte for byte (tests/test_partitions.py).

    5. Members¶

    recast members --data work/data --partitions work/parts.json --keys 42,43 --runs work/runs -- --epochs 20

    trains the 18 members of every key: the five strain estimators (presets A0, aff, full, spr30, uni) and the atom fit (sat), three initializations each, with the hyperparameters of the paper's DFT correction (recast.train.PRESETS); --presets restricts the member types. On a cluster, write one line per member type, seed and key and run them as a job array:

    recast jobs --data work/data --partitions work/parts.json --keys 42,43 --runs work/runs -o work/lines.txt \
    --device cuda --sbatch work/train.sbatch --account ACCOUNT --partition gpu --time 02:30:00 --gpus 1 -- --epochs 300
mkdir -p logs && sbatch work/train.sbatch

    The lines give the same members as recast members (each key is seeded at its start). Every member minimizes the volume and shape errors of its strain (the cell loss of the Theory page). Options after -- go to recast train, which trains one member type and accepts every hyperparameter on the command line. The MLIP corrections of the paper used their own settings; their values are in the args_<key>.json files of the released networks.

    6. Selection and scores¶

    recast select --data work/data --keys 42,43 --metric cell:shape work/runs/A0_s0 work/runs/A0_s1

    compares candidate runs by the mean over the keys of a test-set error (cell:shape for a cell member, the bond-length error at the experimental cell cellO+final:bond for the atom fit) and marks the lowest. In the paper, candidates were compared on the development folds only; the reported test sets were scored once.

    7. Release and test errors¶

    recast export --runs work/runs --keys 42,43 --data work/data -o work/release
recast evaluate --release work/release --data work/data --partitions work/parts.json --keys 42,43 -o work/scores.json
recast correct new.vasp --release work/release --inputs toy -o work/out

    export writes the release folder (manifest.json with the sha256 of every file and the names of the featurizers, members/<tag>/). evaluate scores each key's own test structures with that key's members: the mean of the 15 cell members' strains and the atoms of the three atom-fit members. correct then uses the release like the published one.
